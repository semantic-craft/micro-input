# Micro Input

面向 Work Louder Creator Micro 2 的独立 macOS 配置器与宿主服务。技术方向：**Rust 核心 + SwiftUI 界面**。项目名为工作名。

## 当前开发状态

首轮原生离线工作台：纯 Rust 七核心模块（`mi-proto`、`mi-transport`、`mi-model`、`mi-session`、`mi-bridge`、`mi-macos`、`mi-core`）+ 薄 C-ABI 边界（`mi-ffi`）+ 原生 SwiftUI 界面（`app/MicroInput`）。支持配置浏览、动作搜索/分类、结构化动作参数、Profile/Layer新建/复制/改名/排序/删除、本地普通宏按下/释放/延时步骤编辑与共享引用管理、四分支 Multi 的本地时序与共享动作引用编辑、本地草稿持久化、结构与动作差异及整次撤销/重做。动作库按名称、分类和目标搜索，收藏作为独立本机偏好保存；动作条目显示目标、前提与执行不可用原因，应用意图通过系统选择器选择目标。主窗和菜单栏共享状态；关闭主窗保留菜单栏，退出结束会话。⇧⌘M打开菜单栏面板，⌘E搜索动作，⌘[/⌘]选择控件，⌘D查看差异。

```sh
scripts/verify-offline # 全量检查 + 六个隔离合成应用场景 + 自动回执/清理核对；不连接真实设备
scripts/perf-baseline # 隔离 QA 冷启动与空闲 CPU/RSS 基线；只测量，不设验收预算
scripts/check          # Rust/Swift测试、C-ABI 静态库与开发包构建、协议与架构边界检查
scripts/run            # 启动当前checkout的target/MicroInput.app
scripts/run --verify   # 独立QA标识/文档，10分钟自动退出并回收副本
```

需要macOS14+、Rust stable、Swift工具链。构建不加载凭据。仅本地ad-hoc开发签名，未正式发布。

启动载入所选本地草稿，无文件时载入合成配置；点击“查找 / 刷新 USB”后只读枚举 USB HID 描述符并持续监听插拔，不会打开硬件或申请权限。候选经完整 usage pairs 与 OS USB 来源筛选，多候选必须明确选择；0x8297 标为未验型号；候选只展示 OS 身份，显式查询前固件显示未知。插拔事件更新候选，选择不读取或应用设备配置。本地文档默认在用户Application Support/MicroInput/workbench.json；v1浏览不改文件，首次修改先备份原字节再保存v2。设备快照保持只读，点击“从快照新建草稿”才保存独立draft-UUID.json；原工作台保留，所选文档记录带锁/冲突检查，退出重开继续新草稿。参数表单需点击保存，撤销历史仅在当前会话。原生配置应用限已核验的唯一 USB Creator Micro 2 / 0.6.3 当前连接，宿主动作能力见下节。支持显式USB身份查询，当前303A:8298/固件0.6.3已在应用路径读回；显式身份为受支持的0.6.3后可读取两份限定配置文件，按块校验原始SHA-1并再次list，再一次发布只读快照。查看设备不会改变本地草稿，返回后保留编辑与撤销。核验快照可与文档基线、本地草稿作三方比较；整份保留本地、采用设备或取消均需明确选择，不写设备。接受前先保存不可覆盖恢复副本，再原子保存并清空跨基线撤销；身份不确定、源 ID 歧义或未知原值变化禁用自动合并，临时接口变化须先核对并确认同一设备，确认仅对当前会话快照有效；已知身份不同仍不能套用基线。其他固件仍拒绝读取，不把演示或导入数据作为设备快照。

系统睡眠通知由 Swift 转发给 Rust `mi-core`，使旧输入、连接和待完成结果失效。核心停止自己启动的原目标听写，关闭 USB 会话，保留本地草稿及会话内撤销历史；旧快照标为过期。唤醒等待旧读取线程和六层后台任务释放，只恢复此前开启的描述符发现，不自动连接、查询或写入设备。停止听写未确认时保留失败状态。旧自定义按住听写动作若没有受支持的原目标 AX 控制，明确拒绝执行；通用 Fn 快捷键仍可按原方式使用。观察者随应用退出注销。合成通知与核心回归不能替代真实合盖、锁屏、物理拔插和录音效果验收，见[E-096](docs/spec/EVIDENCE.md)。

输入监视支持候选绑定观察（`subscribe_input`）与已核实宿主路由流（`subscribe_verified_input`）：在固件 0.6.3 硬件透传层（`AG00–AG18`）就绪时，`VerifiedInputDecoder` 按实机核验映射第 0 行按键（左键 `AG00` → `logical-0`，右键 `AG01` → `logical-1`）与摇杆 4 扇区偏移（`AG15–AG18` → `logical-16–logical-19`）；底行左中微动（`AG10` + `AG11`）支持在主机偏好（`bottom_row_layout`）中全局切换**拆成两个按键（`split`，1U + 1U 默认）**与**合并为 2U 宽键（`merged`，双微动按位掩码合并为单次触发）**。菜单栏与单屏工作台支持启用 Mac 宿主动作执行、内置桌面 Agent 预设（Antigravity、Herdr、Codex、DeepSeek Harness）与非 Agent 通用兜底预设（「其他软件」，通配 `bundleID = "*"`，底排中间麦克风键 `AG11` 预置为苹果 Magic Keyboard 原生 `Fn` 🌐 语音键 `0x3F`，所有键位均支持内联录制自定义快捷键）及零 Flash 写入切换 `host_active_profile_id`，详见[宿主动作执行与 Coding Agent 预设架构](docs/designs/host-execution-and-agent-presets.md)与 [E-098](docs/spec/EVIDENCE.md)。

旋钮三个逻辑槽位可独立分配本地动作；摇杆可选择保留来源模式或编辑本地逻辑扇区。减少活动扇区或切换模式不会删除旧槽位及绑定，未知物理方向继续标识；0–32 是本机编辑器限制，不是设备容量。保存、撤销/重做和重开沿用本地文档服务。见[控件编辑契约](docs/implementation-plan.md#t10-本地控件编辑契约)。

“本地文档”提供恢复与另存：列出本机草稿、迁移/重连副本和中断文件，也可明确选择来源；先显示版本、来源、修订和 SHA-256，确认后创建独立 v2 文档并切换。损坏、高版本和未知字段仅可另存原始字节副本，不转换或重置；当前草稿遇到原件并发变化或中断保存时，可另存独立文档继续编辑。来源、原工作台和中断记录保留，选择记录使用既有锁与预期字节检查；选择记录冲突时拒绝切换。v1 恢复复用既有转换，不新增格式。本地恢复不代表设备恢复。见[E-090](docs/spec/EVIDENCE.md)。

“导入与导出”支持整文档、当前配置或当前层的自有 JSON 预设，以及原创 Coding 起步预设。导入先预览，再创建独立草稿；原文档保留，本地对象 ID 重映射，历史设备基线不作为当前设备事实。为保留未知原值，导出仍包含完整来源档案，保存前会提示；不宣称兼容厂商格式。见[预设交换契约](docs/implementation-plan.md#t11-自有预设交换契约)。

“导出诊断”生成结构化报告，记录应用版本、系统版本、连接阶段、候选数量、文档来源和修订、设备能力、输入监视状态、脱敏状态文本、最近失败及最近宿主动作结果。默认排除配置内容、原始回包、序列号、命令文本和文件路径；序列号标记为 `[redacted]`，JSON 载荷标记为 `[redacted-payload]`。报告仅用于故障排查，不代表设备、实体键或灯光视觉验收。

Agent 可通过 `target/debug/mi draft read/validate/patch` 读取已保存的本地文档、校验受限操作并生成独立提案。工作台“审阅 Agent 提案…”显示来源修订、摘要和逐项差异，拒绝保持当前草稿，接受才创建独立草稿。过期身份/修订/原字节、非法字段、悬空引用与保存冲突均拒绝。示例：`scripts/draft-client.py /absolute/workbench.json /absolute/proposal.json '新配置名称'`；CLI 只支持配置/层改名及已有本地动作绑定，不创建新动作、不控制设备或执行宿主动作。协议、错误码与来源保全见[T29 契约](docs/implementation-plan.md#t29-agent-本地提案契约)。

“准备应用键位或灯光”提供多个普通设备按键和已有 RGB 字段的统一预览：将已知的六项 DeviceKey 意图与宿主快捷键分开，只接受来源明确且无其他结构变化的草稿。预览绑定当前会话核验快照、文档身份/修订/原字节摘要，显示来源 Profile/Layer/逻辑槽和前后值；活动索引不用于猜测目标。明确保存后，在私有目录保存两文件原字节/有无、元数据、计划身份与统一配置编译候选，fsync 并读回核对；不覆盖旧包。USB Creator Micro 2 / 0.6.3 的原生应用与同连接恢复已接通（E-108）；副本本身仍不代表恢复成功。见[T13 准备契约](docs/implementation-plan.md#t13-单基础绑定准备契约软件准备设备应用仍未开放)与 E-097。

规格见 [SPEC](docs/spec/SPEC.md)、分阶段验收见 [BUILD_PROMPT](docs/spec/BUILD_PROMPT.md)、[证据](docs/spec/EVIDENCE.md)和[未知项](docs/spec/UNKNOWNS.md)。

“读取并编辑设备配置”建立独立设备草稿，Mac 宿主草稿及其当前控制目标保持不变。设备工作区只编辑普通键和已有 RGB 字段；原生候选仍限定六项已知普通键 token，旋钮、摇杆、宏和结构变更不在本轮写入范围。逐项变更在同一审阅面板显示，备份、写入和恢复沿用现有流程。返回宿主草稿保留原撤销状态；重开默认进入宿主，另可继续已保存设备草稿。继续旧草稿不读取设备，旧基线必须比较；“从当前设备新建草稿”使用新鲜读取结果并保留旧文件。

## S3 配置应用

左栏提供本地六层方案，默认依次为 Codex 原生、Antigravity、DeepSeek Harness，以及三个未分配层。USB 启动方案单独保存；六层预览显示三个 LED 的组合，不代表设备已切层。当前六层「应用到键盘」入口明确拒绝，直到完整输入与写入路径验证完成。旧本地方案和设备映射保持原样；含已退役应用的六层安装暂停执行，保留原设备备份与恢复入口。

旧偏好迁移保留稳定 ID、顺序、显式空槽、缺失引用与其他偏好，首次保存前创建原始 v1 字节备份。旧三层运行绑定与可编辑六层方案分离；只有当前连接确认旧 Profile、固件与首层握手后才恢复旧路由，缺失绑定时暂停。编辑、默认重置、预览及重开均不从新方案推断旧运行目标。旧三层识别、编译和恢复协议保持原语义，旋钮和摇杆共享报告仍暂停转发。

USB 匹配线程先尝试独占再通知工作台；已独占时新开的原生客户端不能读写该接口。macOS 发布接口到独占成功之间仍可能有竞争，真实实体换层和按键另行验收。

Rust 模型已支持 Layer 可选灯光目标、单区/当前Profile多层编辑、撤销/重开/复制及自有预设往返。准备器支持多个普通键（包含有限已知AG/ACT原绑定）与已有灯光字段的混合候选；未知字段、另一灯区和其他映射保持原字节。保存副本后冻结计划仍可取得一次，受支持原生连接与专用合成实例均可执行应用/同连接恢复流程。

`cargo test -p mi-model --test lighting` 验证文档与候选；`cargo test -p mi-session --features synthetic-backend --test config_write` 用实际codec/framer/唯一reader和可变合成文件验证写回、恢复及失败路径。原生与合成后端共用计划绑定的 ConfigWriter、高层 FFI 和恢复界面；原生入口独立核验型号、固件和连接，普通 RPC 接口仍只读。

下一段离线恢复已实现：备份目录内持久操作记录绑定原副本、候选和冻结文档；首次可能发送前落盘，重开不续写。合成环境支持损坏 keymap 的显式新计划恢复、独立读回核对，以及只修本地保存的幂等重试。

高层 FFI、宿主动作排空、逐绑定重验及恢复界面已接入专用合成后端（E-102）。这不是完整 S3 交付：两区 RGB 编辑与合成预览生命周期已接入；E-108 已接通真实配置应用并完成最小 RGB 字段变更及原字节恢复；即时原生预览已接通离线路径，实体效果未验收。默认自动验证仍不连接真实设备。方案见[设备改键与RGB设计](docs/designs/device-write-and-rgb.md)。

RGB 面板提供 Backlight / Underglow 的六种已知效果、六位颜色值及可用的亮度/速度/Magic 参数，禁用或未知字段保留原值；当前配置全层修改为一次可撤销操作。预览是显式临时状态，既不修改草稿也不写 keymap，30 秒自动结束，关闭面板/退出时显式结束。合成状态机使用专用 `synthetic.lights.*` 测试消息证明顺序、目标绑定、独立运行态读回与失败行为，**不是官方 `lights.preview` 的已验证实现**。原生入口复用当前核验连接，发送所选草稿两区值；停止只取消后续发送，不自动恢复、不声称运行态读回。

`scripts/verify-offline` 自动执行统一门禁、构建合成应用、依次跑宿主、DSH 导航、Antigravity 状态、配置、灯光和诊断导出六个隔离场景、核对回执与清理并生成每轮 `result.json`，最后恢复生产构建而不启动它；任何缺失回执或错误地宣称物理/视觉通过都会失败。诊断导出场景注入一条脱敏配置读取失败，自动生成报告和回执。`--qa-only` 只省略单元门禁，仍构建、验收和清理应用。

## 常用 Agent 与日常界面

菜单栏采用原生锚定弹出面板：四个常用配置以 2×2 按钮完整平铺（默认第一行 Antigravity、DSH，第二行 Herdr、Codex；“其他配置 → 调整常用配置”可逐位置更换，已置顶项会交换位置，排列自动保存），无需滚动即可切换当前控制配置；其他配置与连接详情使用次级菜单，支持暂停按键控制和打开工作台。工作台的六层配置列表独立于当前宿主控制目标，允许选择受保护的原生方案或明确留空。设备状态只显示当前连接实际确认的旧三层信息，浏览第 4–6 层不会改变它。现有运行路径仍使用 Creator Micro 2 的 USB 专用接口；六层共存与实际设备安装尚未完成。工作台采用浅绿强调色、常用 Agent 侧栏、按键预览与动作编辑区；设备发现和输入监视收在“设备与连接详情”。浏览配置不会改变当前控制目标，需点“启用此配置”。

菜单栏新增“自动跟随前台应用”“应用关联…”和“按键速查”。自动跟随默认关闭；选择应用并关联稳定 Profile 后才生效。未关联应用保持上一套；手动选择（包括重选当前配置）保持到“恢复跟随”。切换成功后显示 1.5 秒提示，速查显示实际宿主 Profile 的首层映射，不显示文本内容或执行按钮。启动保留已有选择和按键暂停状态；输入流丢失时使用“恢复输入”，松开按键、摇杆回中后再触发。径向菜单默认关闭，可在菜单栏开启；先回中，再用摇杆八向选择、旋钮按下确认、回中取消。固定入口提供后退、前进、按键速查和五个内置应用入口，缺少目标时显示禁用原因。仅使用当前已核验映射，不写设备；实体手感与多屏仍待验收。设计与边界见 [S5](docs/designs/app-following-and-hud.md)。

首次安装提供四套内置 Agent 预设，默认打开 Antigravity。要控制其他应用，在左侧选择「其他软件」，点画布上的按键，在右侧录制快捷键并启用这套配置。未指定目标时，快捷键发送给当前前台应用。

“试运行此动作”使用同一 Rust 路由与真实 Mac 执行器，要求当前编辑配置已启用且按键控制开启。自动验收使用合成输入，原生应用结果和实体按键另行记录。

启动时补齐缺少的常用配置；移除“安装 Coding 起步预设”入口，并在预设安装时仅移除与内置来源完全相同、没有动作或控件设置修改的演示／示例配置。已编辑、改名或导入的配置保留；安装与移除作为同一次可撤销修改保存，重复安装不覆盖已有同名配置。

### 桌面 Agent 常用控制

## 按住说话

重新安装常用 Agent 预设后，未修改的 Codex、Antigravity 和 DSH 预设将听写键升级为“按住说话 · 松开停止”；其中 Antigravity 预设将 `logical-7`（开关 08）设为聚焦当前输入框，默认底行采用双 1U + 1U 布局：左键（`AG10` / 开关 11）在项目中新建会话，中键（`AG11` / 开关 12）按住说话 · 松开停止，右键（`AG12` / 开关 13）发送消息（先停听写），切回 2U 合并布局时宽键自动触发按住说话。按键按下时确认原应用的录音状态，松开时只停止本次启动的听写，不自动发送。原有用户自定义动作不会被预设升级覆盖；`dictation` 仍表示点击切换，`push-to-talk` 表示实体按住手势。工作台“试运行”保留点击切换行为。

宽键复用已验证输入流的合并结果，最后一个微动开关释放才结束手势。切换配置、修改草稿、暂停输入、输入流缺口、队列溢出、切到其他应用、断连、睡眠和退出都会结束当前手势。最长按住时间为 120 秒；开始和停止各有 8 秒等待上限。超时不代表原应用没有执行操作，迟到启动仍只清理原目标。

目标锁定到原进程实例、窗口及 AX 控件，不是应用内部的会话 ID。停止动作仅发往原控件。已尝试停止后，若原进程实例、窗口身份及标题仍相同，允许完整扫描原窗口内唯一空闲控件来只读确认；不会对替代控件执行操作。停止未知会阻止后续按住说话及配置写入，并在菜单栏显示“复核原听写已停止”。该按钮只回读原控件、上述原窗口空闲状态或确认原进程已经退出，不重放切换动作。当前应用内部同窗会话切换仍须原生验收，不据此宣称会话级身份锁定。

验证入口见 [按住说话验收](docs/verification/push-to-talk.md)。合成输入与真实应用启停分别登记，不能代替实体键帽和麦克风转写验收。
