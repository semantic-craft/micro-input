## 交付顺序与完成条件

1. 按住说话。复用输入合并与听写状态回读；默认松开停止、不发送。目标在开始时锁定。开始失败、重复边沿、释放早于开始完成、切 Profile、断连、睡眠、退出不得误启动录音或停止其他目标。先行为回归，再项目 check 和隔离原生验收。
2. T3 Code 待处理会话。先核实实际安装版本和支持接口。读取状态元数据，固定会话身份，选择等待较久且未在本轮访问的目标，精确打开并确认。不实现自动批准或发送提示词。旧快照、断连、目标消失不得误开其他目标。未读事实不可由完成状态猜测。
3. 状态灯。以 v.oai.thstatus / v.oai.rgbcfg 为候选证据。先核实当前层、运行状态读取与恢复。现有 lights.preview 的停止发送不等于恢复。恢复证据不足不发新灯光写入，记录独立阻塞，不阻塞会话导航。
4. 径向菜单。复用当前宿主路由与目标，非激活窗口，选择/取消状态机。保留现有 v.oai.rad 的已验证角度与距离，选择八方向菜单；旋钮按下确认，摇杆回中取消，不使用未经验证的回弹速度。菜单默认关闭，既有四向动作保留。物理手感与斜向命中仍待验。先纯状态机与隔离UI，再实体输入；无映射写入。
5. MCP/CLI 服务出口。暂缓，只有实际消费者需求时接入。

## 协调规则

- 本协调任务仅有一个代码实现者。宏会话另有负责人，独立工作区不互写；共享入口在集成时逐提交核对。研究可并发，设备和原生UI验收须核对全项目占用后串行执行。
- 各实现分支有唯一写入负责人，独立核验者读取具体 SHA/diff 与运行证据。
- 共享 Store、执行器、路由变更顺序集成，合并前刷新主线。
- 原工单 #24 覆盖灯光、#35 覆盖径向菜单；不重复创建。新范围在核实后补明确子工单。
- 仅在真实阻塞或产品取舍时请求用户。常规验证、提交、PR与合并沿用户授权执行。合并不能冒充安装版或真实硬件验收。
- 同一失败连续两轮不能解决时，重新核对前提并缩小切片，不盲目重试。
- 不创建额外定时器。协调在本会话继续，恢复时先核对实际版本和验收。
