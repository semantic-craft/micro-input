# 运行状态、动作归属与输入边界

Micro Input 保留 Rust 核心、同步 C ABI 和 SwiftUI 主线程薄壳。内部重构以用户行为为契约，界面读取不推进运行状态，已开始动作由原所有者清理，输入过载明确失效。

## 调用契约

- `dispatch_command` 接收用户意图，修改状态并明确执行所需的宿主同步。
- `poll_hardware_events` 接收后台完成结果和有限批次输入，推进到期状态。
- `projection` 只读取已发布的界面数据，不执行所有权轮询或原生面板操作。
- `HeldInputId` 以连接身份和绑定标识定位一次持续输入。释放不接受当前 Profile 或当前目标。

连接身份、系统生命周期 epoch、执行许可代次和投影 generation 分别表达设备来源、后台任务代次、动作准入和可观察界面变化，不能互换。

## 投影与执行

状态更新阶段完成 modal、收藏和可见映射提示的规范化，并采样所有权、应用可用性和六层运行事实。投影只消费这些值。原生 HUD、径向面板和菜单栏通过明确的展示同步步骤更新，保留主线程执行约束。

窗口焦点由浮窗控制器保存，不属于公开界面投影。只有可见内容变化才推进渲染 generation。重复选择和不改变可见内容的窗口通知继续在 FFI 层短路，不重新序列化整份投影。

浏览 Profile 或六层预览只改变编辑对象。它们不能激活宿主、改变运行所有权或停止已经开始的动作。异步所有权结果仍由当前 epoch 的运行更新消费，不能依靠读取界面顺带完成续租。

## 动作所有者

`LiveHostActionExecutor` 是 Fn 输出及其持有记录的唯一所有者。工作台与六层线程共享同一个 `Arc`，所有宿主操作从准入检查到完成都串行执行。记录保留按下时的 Profile 和目标。第一个持有者发送系统按下，最后一个持有者成功释放后才发送完成回执并移除记录。释放失败保留清理责任，期间拒绝新的宿主动作。

瞬时 Fn 脉冲也经过同一执行器的资源管理，不能通过一组独立 down/up 提前结束其他持续输入。生命周期所有者先停止并等待旧执行线程退出，再确认动作清理；线程退出本身不清空共享资源。径向菜单保留执行器返回的成功或失败回执。

六层请求在宿主执行锁内再次检查停止标志与执行许可代次。禁用后重新启用会产生新的许可代次，旧请求不能恢复执行；策略切换前已接收的积压输入也不进入新代次。

PTT 保留原连接、绑定和目标归属。原生 `ManagedAxControls` 继续持有原窗口身份。单个 PTT 的松开只停止听写，不释放独立 Fn 持有者；输入源退役、睡眠或退出才清理该所有者全部动作。开始或停止未确认时，不把资源当作已经释放。

## 输入与时间

硬件输入有容量限制，每轮消费有数量预算。数据积压不能阻止断连、所有权完成等控制结果交付。输入缺口使用独立的持续失效标记，先清理原动作并关闭该输入源，直到建立新的有效连接；不重放丢失区间，也不猜测物理按键已经松开。

连续状态更新可以合并，但按下和释放不得任意合并。旧连接生产者不能影响新连接，旧生命周期完成结果不能改变当前运行状态。

领域逻辑继续使用 `Instant`，由消费边界传入时间。回放固定事件顺序、批次边界和时间偏移。HID 壁钟时间戳不充当单调时间；真实 USB 和 AX I/O 超时仍由驱动维护。批次有界不等于单次宿主调用有硬实时保证。

## 设计取舍

两份候选分别探索领域内局部边界和统一运行资源所有者。采用局部边界，吸收统一所有者方案的可靠断连信号及消费时间语义。独立交叉评审要求保留执行器的单一 Fn 账本，避免在 Store 复制一份资源状态。

实现复审发现六层线程和径向菜单能够并发执行，单靠执行路径交接不能保证互斥。针对这一约束重新比较了共享整个执行器和仅共享 Fn 资源两种结构。选择共享执行器，让听写目标所有权与宿主准入也集中在同一边界，并由 Store 明确负责最终清理。原生面板继续留在主线程；宿主调用的串行化不提供耗时上限。

暂不引入后台 Store actor、通用 Effect 框架或新的原生听写 token。它们会扩大同步 FFI、主线程回调和资源交接的协议，而当前需求可在已有所有者内完成。

## 来源与验证边界

- [Crux App](https://github.com/redbadger/crux/blob/master/crux_core/src/lib.rs) 提供状态转换、外部操作请求和界面投影的职责参照。
- [Karabiner manipulator manager](https://github.com/pqrs-org/Karabiner-Elements/blob/ac37d842a7b5ff503b5ccedba7a0c246d3d45d22/src/share/manipulator/manipulator_manager.hpp) 提供旧规则退役后仍完成活动动作的参照。
- [Kanata keyberon Layout](https://github.com/jtroo/kanata/blob/184b63825b7c0da0be0f573ec81dc3520dff6f97/keyberon/src/layout.rs) 提供显式时间推进和队列溢出处理的参照。
- [Input 研究](../input-architecture.md) IA-01、04、09、11、13、16 约束异步回执、输入来源、宿主执行和断连清理；[模块契约](../module-contracts.md) 继续区分设备快照、本地草稿和宿主状态。

验证包含原归属释放、多个 Fn 持有者、失败清理、输入缺口、旧来源隔离、投影纯度和确定时间回放，以及项目全量离线验收。合成结果不证明真实录音、实体按键、灯光效果或设备写入。本轮不增加固件协议或设备变更。
