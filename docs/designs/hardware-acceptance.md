## H0：执行前才采集的备份

1. 确认本次执行授权、唯一明确的 USB 303A:8298 目标与固件 0.6.3，记录当前连接的设备描述符。接口路径仅是连接定位，不能单独证明跨连接同设备；当前协议没有已核实的稳定硬件 ID。执行器要求显式路径、唯一候选和固定固件，在同一打开句柄内采集并核验；H1另核对操作者提供的 keymap SHA-256，拒绝跨连接恢复或沿用旧备份。此约束不宣称路径加配置摘要能唯一识别物理设备。
2. 查清已有操作日志与临时文件未决状态。确认官方 Input 和其他可能发送设备请求的客户端已停止干预；不得由脚本自动终止别人的进程、切 Profile 或启动官方 Input。静默窗口和未见外部流量不能证明独占。
3. 用只读入口取得 `device.status`、完整目录，以及 `keymap.json`、`smart_actions.json` 原始字节。缺失 smart_actions 与空文件分别记录。只读前后核对目录 SHA-1、大小与已知活动索引，再重复完整读取确认稳定；不解析重排原 JSON作为备份。
4. 在本轮新的私有目录保存设备身份、固件、时间、活动索引、目录元数据、两份原字节与各自 SHA-1/SHA-256。目录0700、文件0600、不可覆盖，写入并 fsync 后重新读回核对。材料含用户配置，只留 Git 忽略区，不复制进 PR 或日志正文。
5. 备份必须来自本次连接的独立核验读取，不能用缓存、演示、导入文件或离线工具的成功代替。H1 每次变更前重新核对连接候选、配置、非目标目录、活动索引与目标预期内容；有变化立即停止。

当前 `prepare-hardware-acceptance` 只接收调用方提供的本地文件，不采集上述设备证据。导入备份始终标 `IMPORTED_UNVERIFIED`；即使文件和摘要全部匹配也不会变成“可执行”许可。

## H1：单临时文件固定实验

先核实目标 `mi_<12个随机十六进制字符>.txt` 在目录中不存在；存在即停止，不能改名后悄悄重试。执行器只允许本次记录中的这一名称，禁止配置文件、任意路径、事务、重启和灯光方法。

| 顺序 | 内容 | 固定发送上限 | 每步通过条件 |
| --- | --- | --- | --- |
| 1 | 新建3078字节测试内容，中文/emoji跨越3072字节边界 | 两块，offset 0/3072 | 全字节读回一致，size/SHA-1一致 |
| 2 | 覆盖为64字节ASCII测试内容 | 一块，offset 0 | 全字节读回恰64字节，无旧尾部残留 |
| 3 | 恢复步骤1的3078字节测试内容 | 两块，offset 0/3072 | 全字节读回与步骤1原测试内容一致 |
| 4 | 删除本次临时文件 | 一次delete | 独立目录核实目标不存在，其他文件保持不变 |

固定最多5个 `fs.writebin` 块，共6220字节；每轮 `append:true`，仅末块 `completed:true`。这些是待检验的客户端候选参数，不能预设 offset 0 必定截断。每步都独立核对两份配置的完整字节、非目标目录及活动索引不变；仅目标目录项允许符合本步的预期变化。不得发送 `keymap.json`、`smart_actions.json`、`lights.preview`、层切换或重启请求。

单RPC预算4秒，总流程240秒，最多一次在途；执行前按真实备份大小计算完整核验所需请求数，不能超过会话不回绕的ID预算。超预算停止，不跳过读回来凑预算。首次可能发送前写入日志，逐块记录发送/收到回应/独立读回三个不同事实。通用成功包络不证明落盘，断连/超时不能靠猜测补成功。

## 停止、保全与恢复

- 身份、活动层、目录或配置变化，外部流量，响应错误/错ID/超时，读回不符，备份落盘失败：立即停止后续变更，关闭会话，保留日志与原材料，结果标 UNKNOWN。不自动重连、不重放、不在 finally 中发送恢复或删除。
- 在首块前失败：记 NOT_SENT，可在新的明确执行流程重新采集基线；不能沿用旧会话许可。
- H1 已发送后未知：先按原日志在同设备只读诊断目标，确认实际存在性、原字节、配置与其他目录项。只有新审阅明确许可且对象仍精确匹配时，才可单独删除或继续恢复；不能“看到同名就删”。步骤3只是正常路径上的测试文件恢复，不是失败后的自动恢复承诺。
- 如果现有配置发生非预期变化：保留 H0 原字节，停止全部测试，不自动用备份覆盖设备。需重新确定原因、设备身份与当前完整状态，单独准备精确原字节恢复方案；不得从磁盘备份存在推定硬件恢复一定成功。
- H2 将来使用现有候选/持久操作记录/独立读回模型：只允许一次审阅的单键变更，写后完整读回，恢复用 H0 的原字节并再次独立读回。原生恢复语义尚未验收，不能先在用户日常键位上故意制造部分写入、断电或拔线故障。此类故障实验只考虑专用测试设备。
- H3 不能以文件备份充当灯光运行态原值；官方面板关闭也不能充当恢复动作。在可靠运行态读取、明确目标和恢复核验未建立前，不发送哪怕一次“短暂改色”。真实灯效视觉不能由RPC成功替代，也没有脚本可证明颜色肉眼正确。

## 离线准备工具

以下命令只有本地文件操作；没有执行、连接、诊断、清理或自动续跑设备的入口。默认输出新的 `.scratch/input-study/hardware-kit-<uuid>/`。不要把输出放进受版本管理目录。

```sh
# 不提供任何现有配置：生成固定计划和两个自编载荷。
scripts/prepare-hardware-acceptance prepare

# 可选：仅封存调用方已持有的本地原字节；不宣称来自设备。
scripts/prepare-hardware-acceptance prepare \
  --keymap /absolute/captured-keymap.json \
  --smart-actions /absolute/captured-smart_actions.json
# 若原采集明确缺失smart_actions，用 --smart-actions-absent；不可默认假设缺失。

scripts/prepare-hardware-acceptance verify /absolute/hardware-kit
scripts/prepare-hardware-acceptance compare /absolute/hardware-kit \
  --keymap /absolute/after-keymap.json \
  --smart-actions /absolute/after-smart_actions.json
```

`verify` 检查私有权限、完整库存、计划固定范围、载荷和备份摘要；它不是签名或来源认证。`compare` 对原字节逐字节比较，缺失与空文件分开。退出码0表示本地检查成功，1表示本地字节不同，2表示输入/完整性错误；输出始终保留 `device_io:NOT_RUN`，`ready_to_execute:false`。材料有效不证明采集时间、设备身份、灯光恢复或实体行为。

离线回归通过项目 `scripts/check` 自动运行，覆盖范围扩张、材料损坏、权限/符号链接/非普通文件、覆盖已有包、缺失/空文件混淆及禁止执行参数。独立执行入口为 `scripts/hardware-acceptance`，不改变本材料工具的离线性质，也不把本地检查成功直接转为发送许可。

## H0/H1 独立执行入口

`scripts/hardware-acceptance` 无参数只运行假 USB 测试，清除继承的探针授权，两个实机用例保持 ignored。`scripts/check` 同样只执行离线回归。实现位于 `crates/mi-session/tests/support/hardware.rs`，不编进生产应用或 FFI，不扩大生产方法白名单。

以下是显式执行入口；再次执行仍须有当轮授权，默认检查不会执行：

```sh
# H0：新鲜只读备份；路径必须由当前操作者明确提供，不自动选择多候选。
scripts/hardware-acceptance --execute h0 --kit /absolute/hardware-kit \
  --device-path '<exact HID path>'

# H1：核清历史未决操作后，使用 H0 记录的 keymap SHA-256。
# H1 在自己的同一连接中重新采集并落盘备份，不拿 H0 磁盘文件替代实时状态。
scripts/hardware-acceptance --execute h1 --kit /absolute/hardware-kit \
  --device-path '<exact HID path>' --expected-keymap-sha256 '<64 lowercase hex>' \
  --unresolved-operations-reviewed
```

启动器验证准备包完整范围，只传固定临时文件名；实际载荷由 Rust 固定生成，不能传任意文件名、RPC 或配置写入内容。H1 在材料包同目录独占创建 `<target>.h1-claimed.json` 并 fsync；无论成功、失败还是启动前中断都不自动释放，重复使用会拒绝。此记录防止正常入口误重放，不是防恶意手工删除或绕过的授权系统。历史 C 记录不会自动读取、清除或被本入口替代。

H0/H1 使用同一专用句柄、串行请求和唯一读取者，ID 0–998 不回绕；4秒单请求、240秒实验、300秒外层进程监督（含编译）。完整配置读取按实际文件大小预留最多14轮读取及额外请求预算；超出预算在写入前停止。H0 保存原始字节，不要求配置JSON能被产品模型解析；缺失和空 smart_actions 分开记录。私有 `probe-h-*` 目录内保存逐阶段记录、原字节、两种摘要、活动索引和目录元数据，文件/目录均 fsync。终态严格区分 NOT_SENT / UNKNOWN / 已核验范围，实体键与灯效视觉仍 NOT_RUN。

H1 在未完成块之间核对原配置、非目标目录及活动索引，完整传输 `completed:true` 后才要求目标文件的最终大小、摘要和完整字节。E-108 实测未完成块对目录不可见；不能以此判定写入失败或强行要求中间文件出现。首次旧执行器在第一块ACK后停止，随后只读核对及单独审阅的剩余块操作没有重发首块，总计仍为5块/6220字节/一次删除。正常执行器没有自动续跑入口。

生产HID发送将一条RPC的所有报告一次持锁连续发送，避免唯一reader的20ms阻塞读取插入分片之间。原实现出现过无合法ID的400错误，未放宽响应校验；改动后原字节恢复通过。其原因关联来自代码竞争分析与修复后的成功，不宣称已穷尽固件错误原因。

无稳定硬件ID、跨客户端竞争和异常断连语义不能由这次局部验收消除。200ms无外来流量窗口仅作冲突检测，不证明独占；每步前后检查也不是固件原子事务。H0/H1工具不做现有配置恢复或灯光恢复，异常时保留备份与记录，禁止自动串联 H2/H3。
