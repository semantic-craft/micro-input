## 实施顺序

- **S0**：规格、证据、UNKNOWN、验收和工单统一。本轮不改变 #1–#6 的完成状态。
- **S1 / #1–#6**：演示桥接 → USB发现 → 应用身份读取 → 设备快照 → 生命周期实机验收。没有安全已知协议路径就保留阻塞，不以缓存/演示替代。
- **S2**：离线草稿、布局编辑、动作库与差异；可在协议补证等待期独立进行，所有输出明确自有格式/未应用。
- **S3**：仅在协议、恢复证据和后续明确授权下实施设备应用/恢复；当前禁写。
- **S4–S6**：Coding适配与必要宿主/菜单栏、可选切换与体验完善、Agent草稿接口。见BUILD_PROMPT各阶段前置条件和副作用范围；不预建自动任务调度。

## 证据进入实现的顺序

先从 [EVIDENCE](spec/EVIDENCE.md) 核对来源、版本、证明范围与冲突裁决，再读其指向的项目行为说明；更新 [UNKNOWNS](spec/UNKNOWNS.md) 后才解锁对应实现。只依据自撰说明与合成向量，不复制原厂Input/wl-device-kit代码/资源，也不读取原Input数据库补模型。

已有 [只读协议](protocol-readonly.md) 补充了node-hid布局、参数/响应、文件校验、设备schema与客户端策略。独立IOKit探针单次sys.version成功只证明该目标/路径，不证明Rust后端、多帧或配置读取。Dispatch是固定提交/0.6.2社区观察，当前设备0.6.3需分别验证。具体字节和schema不在本页重复。

只读生产候选为status/version/list/readbin四方法，限定两配置文件；fs.read为待验证替代路径。13开关矩阵与实体控件分开；usage pairs、权限/Secure Input、manager/缓冲寿命、跨进程ID碰撞、宽键去重和灯光所有权不得被单次成功略过。

已有 [参考仓库](reference-repositories.md) 的检索范围、许可与索引局限继续保留；本轮汇总没有新增第三方源码复用或设备实验。平台自动审查已有配置不在此次任务中修改，也不新增CI/触发器。
