# Architecture decisions

Non-obvious operating system, USB HID, firmware, Karabiner, Accessibility, and storage constraints that shape the codebase live here rather than in inline source comments.

## USB HID transport and macOS run loops

- **Single opening thread for `hidapi`.** On macOS, `hidapi` binds its process-global `IOHIDManager` to the `CFRunLoop` of the thread that first initializes `HidApi`. Short-lived apply or restore workers must never initialize `HidApi` directly, because `CFRunLoopAddSource` crashes after the initializing thread exits. `HidOpenOwner` in [lib.rs](../crates/mi-transport/src/lib.rs) keeps one background opening thread alive for the lifetime of the process and serializes Darwin's global `set_open_exclusive`, `open_path`, and flag restoration sequence even when an open fails. If a caller drops its oneshot receiver before the open completes, the worker drops the returned `HidDevice` immediately on that thread.
- **Descriptor-only `IOKit` matching.** [discovery.c](../crates/mi-transport/src/discovery.c) creates `IOHIDManager` with `kIOHIDOptionsTypeNone` and never calls `IOHIDManagerOpen`, `IOHIDDeviceOpen`, or report I/O. Device opens happen outside the `IOKit` matching callback and off the UI run loop. Raw C string pointers passed into `on_device` in [lib.rs](../crates/mi-transport/src/lib.rs) remain borrowed only for the synchronous callback while `mi_watch` owns the run loop. Matching requires both the vendor usage page (`0xFF00`) and usage `1`.
- **Single-lock multi-report writes.** The background reader in [lib.rs](../crates/mi-transport/src/lib.rs) holds the `HidDevice` mutex during each `20ms` `read_timeout` poll. `MacHidLink::write_batch` acquires that mutex once for an entire multi-report RPC so reader polls cannot insert gaps between `61`-byte payload slices and trigger firmware `400` framing errors. On numbered report `0x06`, [native.rs](../crates/mi-proto/src/native.rs) routes only channel `2` into the RPC accumulator and drops debug or other channels.

## RPC session framing, budgets, and preview leases

- **Monotonic 999 request-ID ceiling.** `DeviceSession` in [lib.rs](../crates/mi-session/src/lib.rs) assigns request IDs `0..999` per connection and never wraps. Recycling an ID could allow a late response from an earlier timed-out call to satisfy a newer request. When `next_id` reaches `999`, `exchange_authorized` records `SessionError::RequestIdExhausted` and disconnects before framing or transmitting any placeholder packet, leaving the reader `JoinHandle` for `shutdown()` to join.
- **Canonical outbound encoding and alias routing.** Inbound routing in [lib.rs](../crates/mi-proto/src/lib.rs) validates `id` and `i` aliases before checking `method` and `m`, preventing an echoed or foreign method string from hiding a matching packet ID. Outbound read-only byte requests in [lib.rs](../crates/mi-session/src/lib.rs) re-encode the validated `RpcRequest` so duplicate JSON keys or alternate string escapes in caller-supplied bytes never reach the wire. `strict_json` in [device.rs](../crates/mi-model/src/device.rs) likewise rejects duplicate JSON keys before `serde_json::Value` deserialization can pick the last key. `fs.writebin` chunking in [mutation.rs](../crates/mi-proto/src/mutation.rs) slices at `3072` raw bytes, allowing multi-byte UTF-8 code points to cross chunk boundaries.
- **Drop guards on partial sends and mutations.** `Sending` in [lib.rs](../crates/mi-session/src/lib.rs) disconnects the session if a caller drops an in-flight write before every report in the batch is sent, preventing a half-transmitted frame from corrupting the next RPC. `MutationGuard` in [config_write.rs](../crates/mi-session/src/config_write.rs) disconnects the session if a caller cancels an in-flight write or post-write verification future after sending bytes.
- **Lighting preview budget and lease teardown order.** `Preview` in [lighting_preview.rs](../crates/mi-session/src/lighting_preview.rs) holds the session queue lock for its bounded lifetime, coalesces slider updates every `80ms` without cancelling in-flight exchanges, reserves two request IDs below `999` for restoration and readback, and compares `expected` runtime light state so external light changes are not overwritten. In [lighting_preview_store.rs](../crates/mi-core/src/store/lighting_preview_store.rs), the `SharedVendorBridge` lease drops only after `Preview::end_future()` finishes so background `v.oai.thstatus` updates or session rotation cannot interleave with preview teardown.

## Creator Micro 2 firmware conventions and ESP32-S3 flashing

- **One-based native layer index and factory `ACT` aliases.** Native Creator Micro 2 firmware `device.status` reports a one-based `layer_index` (`1` maps to `layers[0]`), whereas `synthetic-0.6.3` test fixtures use zero-based indexing in [host_router.rs](../crates/mi-model/src/host_router.rs). Factory Codex layers also emit `ACT00` through `ACT12` aliases, which `verified_bindings` accepts alongside `AG00` through `AG12` without accepting movement or duplicate switch tokens.
- **Normalized radial joystick turns.** On firmware `0.6.3`, `v.oai.rad` notifications in [input.rs](../crates/mi-session/src/input.rs) report normalized screen-space turns in `[0.0, 1.0)` once `distance >= 0.5`, where `0.0` is East (`AG18`), `0.25` is South (`AG17`), `0.5` is West (`AG16`), and `0.75` is North (`AG15`). `InputMonitor` tracks press state across four independent slots (`0` for legacy single-layer input and `1..=3` for managed board layers).
- **ESP32-S3 bootloader identity, `4 KiB` erase alignment, and reset register.** In [firmware_flash.rs](../crates/mi-session/src/firmware_flash.rs), bootloader mode enumerates as Espressif USB JTAG/serial (`0x303A:0x1001`, manufacturer `"Espressif"`) rather than the runtime keyboard VID and PID. Every ESP-IDF data partition except the PHY calibration slot (`type == 1 && subtype != 1`) stores persistent user state. Flash erase rounds up to `4 KiB` (`0x1000`) sectors past the final image byte, so `flash` aborts before writing if the sector-aligned erase end overlaps any persistent data partition. Before toggling `RTS` to leave download mode, `flash` writes `0` to ESP32-S3 register `0x6000_812C`. After flashing finishes, [firmware_store.rs](../crates/mi-core/src/store/firmware_store.rs) sets `resume_requires_explicit_connect = true` and disables `auto_connect_usb` until the user explicitly reconnects.

## Karabiner swallowing rules and six-layer runtime lifecycle

- **Karabiner 16.3 condition order on dual-switch wide keys.** Karabiner-Elements 16.3 evaluates `to.conditions` before executing the `to` action array. In [karabiner.rs](../crates/mi-core/src/karabiner.rs), dual-switch wide keys gate `send` on `{prefix}_latch == 0` while each switch's `key_up_value` leaves the latch set while its peer switch remains held.
- **Fail-safe swallowing rules and non-blocking monitor drop.** Once the board keymap is direct-coded, a failed Karabiner reload in [lifecycle.rs](../crates/mi-core/src/six_layer_runtime/lifecycle.rs) keeps the swallowing rules on disk so unswallowed function keys do not leak into foreground apps. In [six_layer_runtime.rs](../crates/mi-core/src/six_layer_runtime.rs), `RunningSixLayer::drop` calls `retire()` to fence admission immediately and detaches the monitor handle rather than joining a bounded CLI check on the workbench thread.
- **Two-second datagram command TTL.** `MAX_AGE` in [user_command.rs](../crates/mi-transport/src/user_command.rs) is `2s` so a deliberate follow-up click can wait behind a slow AX toggle (`~500ms` traversal plus `~900ms` readback) without replaying stale queued bursts.

## macOS CoreGraphics and Accessibility (`AXUIElement`)

- **Horizontal scroll polarity and pasteboard UTF-8 encoding.** Per AppKit `NSEvent.h`, `CGEventCreateScrollWheelEvent2` in [executor.rs](../crates/mi-macos/src/executor.rs) expects positive horizontal `wheel2` deltas for scrolling left and negative deltas for scrolling right. Objective-C `NSString` UTI construction passes `NSUTF8StringEncoding` (`4`).
- **`AXUIElementRef` cross-thread serialization.** `Owned` in [native_ax.rs](../crates/mi-macos/src/native_ax.rs) wraps a retained Core Foundation `AXUIElementRef`. Its `unsafe impl Send` relies on `ManagedAxControls` guarding `NativeAxProvider` behind a `Mutex`, which serializes all access even when callers hop threads.
- **Pre-submit dictation check and fast pre-mutation browser discovery.** In [managed_controls.rs](../crates/mi-macos/src/managed_controls.rs), `submit_prompt` re-observes and stops dictation right before submitting because a user mouse click can start recording outside Micro Input's key state. `open_browser` uses `BROWSER_PRE_MUTATION_DISCOVERY_TIMEOUT` (`250ms`) before any button press so Antigravity pages without side-panel controls fail fast instead of polling for the `3500ms` post-mutation readback deadline.
- **Directional `AXChildren` path validation.** `AXScrollArea` in Antigravity does not maintain symmetric `AXParent` inverse links (`AXParent` traversal fails at depth 28), so `validate_control_membership` in [native_ax.rs](../crates/mi-macos/src/native_ax.rs) bounds full discovery scans (`MAX_NODES = 16384`, `MAX_DEPTH = 48`) and re-verifies captured controls along their downward `AXChildren` path rather than `AXParent` chains, cutting Antigravity 2.31.0 release `focus_agent_input` median latency from `486.9 ms` to `284.3 ms`.

## C-ABI boundary ownership (`crates/mi-ffi`)

- **Pointer ownership and thread exclusivity across 9 `extern "C"` entrypoints.** [lib.rs](../crates/mi-ffi/src/lib.rs) wraps every entrypoint in `ffi_guard` so Rust panics never unwind across FFI. Caller-supplied C strings are borrowed only for the synchronous call. `mi_core_acquire_instance_lock` and `mi_core_new` return heap-allocated opaque handles released once via `mi_core_release_instance_lock` and `mi_core_free`. `*mut MiCoreHandle` requires exclusive single-threaded caller access per call (enforced on `@MainActor` by `CoreStore`). `mi_core_project_json`, `mi_core_dispatch_json`, `mi_core_poll_json`, and `mi_core_last_error_json` transfer ownership of NUL-terminated UTF-8 buffers created via `CString::into_raw` that the host must release once with `mi_core_string_free`; `mi_core_dispatch_json` and `mi_core_poll_json` return `NULL` when `projection_generation` is unchanged so unchanged dispatches and polls skip JSON serialization and view invalidation.

## Local persistence, file locking, and non-destructive schema rules

- **Deferred truncation on private files.** `PrivateOpenMode::Truncate` in [private_fs.rs](../crates/mi-model/src/private_fs.rs) opens with `O_CREAT | O_NOFOLLOW | O_NONBLOCK` and omits `O_TRUNC` until `fstat` confirms a regular file owned by the current effective UID, preventing symlink, FIFO, or foreign-file truncation.
- **Selective `fsync` and lock ordering.** `DocumentStore::write_current` in [storage.rs](../crates/mi-model/src/storage.rs) calls `File::sync_all()` for board edits, initial defaults, and migrations while keeping runtime routing updates at atomic-rename latency. In [agent.rs](../crates/mi-model/src/storage/agent.rs), `accept_proposal` reports missing documents before creating a `.lock` file in the parent directory and holds the source `.lock` across verification and `select_independent` so concurrent saves cannot race acceptance. In [operation_record.rs](../crates/mi-model/src/operation_record.rs), `retry_local_save` persists verified operation status before locking the target document, and backup restoration requires a live session with matching firmware identity rather than transient OS interface paths.
- **Non-destructive slots, opaque unknown fields, and preset budgets.** Lowering `active_sectors` or changing `joystick_mode` in [control_settings.rs](../crates/mi-model/src/control_settings.rs) never deletes `logical-16..` slots so dormant bindings remain addressable. Unrecognized schema fields or action payloads in [draft.rs](../crates/mi-model/src/draft.rs) mark the draft `read_only` so subsequent saves cannot strip future fields. Scoped exports in [preset.rs](../crates/mi-model/src/preset.rs) retain the immutable source archive (disclosed in UI) while stripping duplicate nested `origin.config` copies during import so exported files stay within the document size budget. Starter installation retires only unmodified factory demo profiles.

## Packaging metrics and one-shot hardware probe kits

- **macOS app icon inset.** [generate-app-icon.swift](../scripts/generate-app-icon.swift) insets the squircle body by `100 / 1024` per side (`824 px` artwork frame inside a `1024 px` canvas), and [verify-app-icon.swift](../scripts/verify-app-icon.swift) validates the rendered frame against a system app bundle icon rather than full-bleed PNG bounds.
- **Durable `H1` kit claim before device open.** [prepare-hardware-acceptance](../scripts/prepare-hardware-acceptance) creates each kit directory with `mkdir(mode=0o700)` so existing kits cannot be overwritten, placing a three-byte UTF-8 character across byte `3071` to exercise the `3072`-byte chunk split. [hardware-acceptance](../scripts/hardware-acceptance) writes `<target>.h1-claimed.json` with `O_CREAT | O_EXCL` and `fsync`s the parent directory before opening the device, never clearing claims automatically after completion or interruption.
