# 验证听写控制

## 六层模式的点击开关

六层并用采用“按一下开始，再按一下停止”，复用已有 Karabiner。先确认 Cindy 原生键盘集成关闭、当前代所有权释放、Karabiner 接管和六层设备读回均已完成。三托管层的按键来源各自固定，不随前台应用变化。

分别在 Antigravity、DeepSeek Harness 和 Cindy 检查空闲→录音→空闲；按住不重复触发，松开不改变录音状态。再用鼠标改变录音状态后按键，确认操作依照实际状态。合并宽键的一次按压只激活一次，两个微动都释放后可再按。没有必要发送识别出的文字。

核对目标应用重启、录音控件重建、目标不明确、权限拒绝与读回超时。调用成功但状态未确认时报告未确认，不自动重试一次开关。Karabiner 或设备换代后旧事件不得执行；Micro Input 退出后自有规则继续吞掉托管键码。

DeepSeek Harness 的语音输入插件需要先启用并准备本地模型；当前控件为“开始录音”和“停止并识别”。Antigravity 的听写入口是 Record voice memo，与 Start Voice mode 分开。录音权限及三款应用的真实 UI 变化均属于原生验收，替代 Provider 的单元测试不能代替。

## 独立的按住说话方案

`scripts/verify-offline` 运行合成宿主场景，并保留启动器和审计回执。`cargo test --locked -p mi-bridge -p mi-macos -p mi-core` 覆盖原生听写控制器、开始确认及输入路由。

在原生验收中，先确认目标应用没有正在进行的录音，再核对目标输入窗口。按下后须从目标 UI 确认录音开始；松开后核对回到空闲。辅助功能调用返回成功不足以证明录音成功。核对过程中无需发送消息。

实体宽键有两个微动。只松开其中一个时继续录音，最后一个松开才停止。听写期间切配置、断连和睡眠时，单独核对原窗口停止。控件身份仅证明操作发送到原窗口，不能代替应用内部会话 ID。

参考 [研究接入规则](../agents/research-context.md) 和 [宿主契约](../module-contracts.md)。听写只消费已核实的输入事件，不需要写设备配置。
