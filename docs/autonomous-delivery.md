# Micro Input 持续交付入口

本项目以 [#44](https://github.com/semantic-craft/micro-input/issues/44) 作为五项交付范围的唯一工单入口。每次接续先核对 `main`、现有 PR、工单、安装版和验收证据，再领取下一项可执行工作。工单关闭、源码合并、安装和真人验收分别登记。

当前适配范围见[四应用控制](designs/four-app-control.md)。Paseo 只作能力参照。用户自建 Profile 可通过通用快捷键控制其他应用。设备写入仍遵守各自证据与授权。

## 五项都要完成

| 顺序 | 范围 | 主要责任票 | 完成证据 |
| --- | --- | --- | --- |
| 1 | 当前能力收口 | #6、#14、#22、#24、#26、#36、#37 | 指定版本的实体输入、灯光、跟随、速查、断连及恢复实际结果 |
| 2 | 常用设备键与层 | #16、#19、#23、#29 | 编辑、应用、物理输出、层状态及恢复连通 |
| 3 | 宏与 Multi | #17、#18、#23 | 按下、释放、延时和四手势实际执行；取消后无残留按键 |
| 4 | 独立日用 | #6、#40、#41、#42、#43 | 首次接入、权限、登录启动、共存、升级和长时运行通过 |
| 5 | 交互与便利性 | #16、#25、#28、#35 | 快捷键捕获、径向菜单、厂商格式交换和通用命令各有实际验收 |

先完成所需的最小技术步骤。某项等待实机或人工观察时，继续不依赖它的工作。任何一项不能从范围中静默删除。需要改变产品目标时，明确记录决定及原因。

## 每次领取一项有实际结果的工作

切片只有同时满足以下条件才进入实现。

1. 用户可观察的结果与验收条件明确。
2. 依赖已经完成或与本片互不影响。
3. 写入负责人及独立工作区唯一。
4. 操作落在已有授权内，实机操作有具体目标和恢复条件。
5. 需要改动的文件、验证入口和当前主线已核实。

条件缺失时直接完成相应研究或准备工作，并把未决条件留在责任工单。每轮须领取一个切片，或说明所有未完成切片各缺什么条件。一个 PR 完成后立即核对下一片，不把 PR 合并当作五项完成。

## 核对真实状态并交付

一个 PR 由一个负责人写入。独立核验者检查实际差异、当前提交和适用的运行结果；协调者核对合并前的主线与检查结果。当前 Codex 环境先只用一个实现者。无法确认旧实现者已停止时，不复用其分支或工作区。

源码、合成应用、真实设备、安装版和人工效果属于不同证据层。每个结果注明提交、构建身份、时间、验证入口和未覆盖部分。设备操作不确定时停止自动重放。旧验收不自动证明新提交或新安装包通过。

默认从 `scripts/check` 和项目 [verify-micro-input](../skills/verify-micro-input/SKILL.md) 选取适用验证。硬件与安装验证仍按项目已有契约。文档或工单对账只核对引用、内容及动态状态，不运行无关构建。

## 自动接续的启用门槛

在有人监督下先完成一项从领取到合并、再领取下一片的实际交付。检查 Codex heartbeat 的串行、worker 存活、暂停和重复触发行为。若无法确认只有一个协调者能写入，heartbeat 只能只读对账，不能无人值守派发。

启用后，同一聊天的 heartbeat 补偿中断，每次先核对现状。运行中完成一片就继续，不等待定时触发。只有新交付、失败、阻塞变化或需要用户操作时通知。五项全部完成且 #44 的最终安装版验收通过后停用自动化。

本文件定义持续范围和接续规则，不把既有最小 RGB 写入授权扩展到新键位、宏、预览或其他设备写入。
