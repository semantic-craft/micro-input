# T3 会话验收

目标是从菜单或已绑定宿主动作打开下一个需要处理的 T3 会话。运行统一门禁后，使用 `MI_AUTO_HOST_READY=0 scripts/run --verify --timeout=90` 启动隔离 QA 实例，并按技能主入口核对 launcher、隔离目录和清理。

1. 打开菜单，确认四个常用配置按钮仍完整显示，T3 连接默认关闭。
2. 开启「T3 Code 只读连接」。确认状态就绪与待处理数量。没有候选时按钮禁用，不打开任意最近会话。
3. 当前已有真实候选时，点击「下一个需要我」。回读 `t3_next_attention` 回执。`delivered` 仅证明系统接受了深链，不是目标身份验收。
4. 用原生 UI 独立核对目标会话身份，再记录 `target_identity_confirmed`。访问水位或标题相同不能单独证明身份。只操作现有会话，不创建、发送、停止或审批来制造场景。
5. 关闭连接，确认菜单候选清空。退出后核对 launcher 清理，并记录短期会话撤销结果。

`T3AttentionTests` 覆盖模拟待办优先级、子会话汇总、休眠提前唤醒、轮次、冻结目标、并发刷新、服务倒退、真实 UniFFI lease 与睡眠门禁、只读请求头、取消迟到签发撤销、重定向拒绝和输出上限。显式 `MI_T3_READONLY_PROBE=1` 可验证已安装 T3 的真实只读读取及撤销；默认测试跳过此项。

结果分列软件状态、真实读取、原生目标定位、真实 pending/failure/unread 转换、实体输入及灯光。当前没有真实待办时，目标定位和状态转换记 `NOT_RUN`，不能用合成测试替代。灯光记 `BLOCKED`，原因是恢复条件未核实。保存 result.json 时不含标题、正文、环境/会话/请求 ID、凭据或深链。
